# 広告表示前3分待機計画

## 概要

RPPトラック系の処理が成功してから、広告表示（RPP-unyou）の処理を始める前に約3分待つようにする。

1分ごとの `processInputFolder()` トリガーは維持し、待機中は後続ファイルを `input` フォルダに残したまま、3分経過後の実行で広告表示を処理する。

## 実装方針

- `Utilities.sleep(3分)` は使わない。
- `PropertiesService` にRPPトラック完了時刻を保存する。
- RPPトラック系が成功した回では、広告表示の前に待機状態を保存して処理を終了する。
- 次回以降の1分トリガーで、保存時刻から3分未満なら広告表示と楽天サーチは処理しない。
- 3分以上経過していれば、広告表示を処理する。
- 広告表示の後、楽天サーチは従来どおり続けて処理する。
- 待機中の広告表示ファイルと楽天サーチファイルは `input` フォルダに残す。
- 待機完了後に広告表示が成功または失敗したら、待機状態をクリアする。
- `README.md` に広告表示前の3分待機仕様を追記する。

## 変更対象

- `src/コード.js`
  - 待機時間と `PropertiesService` 用キーを定義する。
  - RPPトラック完了後に広告表示前待機へ入る処理を追加する。
  - 3分経過判定、待機状態の保存・取得・削除を補助関数化する。
- `README.md`
  - 固定順処理と広告表示ペア処理の説明に、RPPトラック成功後の3分待機を追記する。

## テスト観点

- RPPトラック系、広告表示、楽天サーチを同時に `input` へ置いた場合、1回目の実行ではRPPトラック系だけが処理される。
- 3分未満の次回トリガーでは、広告表示と楽天サーチが `input` に残る。
- 3分以上経過後のトリガーで広告表示が処理される。
- 広告表示成功後、楽天サーチが続けて処理される。
- RPPトラック系でエラーが出た場合は、現行どおり後続処理を実行しない。
- 広告表示でエラーが出た場合は、現行どおり楽天サーチを実行しない。

## 前提

- 待機を入れるのは「RPPトラック系」完了後から「広告表示」開始前だけ。
- 「広告表示」完了後から「楽天サーチ」開始前には待機を入れない。
- トリガー間隔は現行の1分ごとのまま変更しない。
- 子GAS側の処理内容やURLは変更しない。
- 待機中の後続ファイルは `input` フォルダに残す。
