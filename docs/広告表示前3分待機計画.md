# 広告表示前3分待機計画

## 概要

RPPアップファイル一式をまとめて `input` フォルダへ入れたとき、RPPトラック3種を固定順で処理し、その完了後に約3分待ってから広告表示（RPP-unyou）を処理する。

確認した一括アップロード対象は以下の6ファイルとする。

- `YYYYMMDD_item_list.csv`
- `rpp_item_reports_limelimedou_YYYYMMDDHHMMSS*.zip`
- `rpp_keyword_reports_limelimedou_YYYYMMDDHHMMSS*.zip`
- `rpp_item_keyword_limelimedou_YYYYMMDDHHMMSS*.csv`
- `rpp_keyword_ranking_limelimedou_YYYYMMDDHHMMSS(_n).csv`
- `act_*.csv`

## 実装方針

- `Utilities.sleep(3分)` は使わない。
- `PropertiesService` に広告表示前の待機開始時刻を保存する。
- RPPトラック3種は以下の順で処理する。
  1. `YYYYMMDD_item_list.csv`
  2. `rpp_item_reports_limelimedou_YYYYMMDDHHMMSS*.zip`
  3. `rpp_keyword_reports_limelimedou_YYYYMMDDHHMMSS*.zip`
- RPPトラック3種がすべて揃って成功した場合だけ、広告表示前の3分待機を開始する。
- `item_list.csv` だけ、またはreports系ZIPだけでは、広告表示前の3分待機を開始しない。
- RPPトラック3種が揃っていない場合は、対象ファイルを `input` に残し、次回の1分トリガーで再判定する。
- 3分未満の次回トリガーでは、広告表示ファイルと楽天サーチファイルを `input` に残す。
- 3分以上経過していれば、広告表示CSVペアを処理する。
- 広告表示の後、楽天サーチは続けて処理する。
- RPPトラック3種の日付キーは完全一致を要求しない。
  - `item_list` の日付とreports系ZIPの出力日時がずれるため。
- `README.md` に実ファイル形式と待機条件を反映する。

## 変更対象

- `src/コード.js`
  - RPPトラックreports系の固定順判定を `.zip` に変更する。
  - RPPトラック3種の揃い判定を追加する。
  - 3種成功後だけ待機開始するように待機開始条件を修正する。
  - 3分経過判定、待機状態の保存・取得・削除は `PropertiesService` で行う。
- `README.md`
  - RPPトラックreports系はZIPであることを明記する。
  - RPPトラック3種が成功した後に広告表示前3分待機へ入ることを明記する。

## テスト観点

- 6ファイルを同時に `input` へ置いた場合、RPPトラック3種が指定順に処理される。
- `item_list.csv` 処理後すぐに広告表示へ進まない。
- RPPトラック3種がすべて成功した後、広告表示前に3分待機する。
- 3分未満のトリガーでは広告表示と楽天サーチを処理しない。
- 3分以上経過後のトリガーで広告表示CSVペアを処理する。
- 広告表示成功後、楽天サーチを続けて処理する。
- RPPトラック3種のうち不足がある場合、広告表示には進まず、対象ファイルを `input` に残す。
- RPPトラック処理中にエラーが出た場合は、現行どおり後続処理を止める。

## 前提

- まとめてアップする対象は、確認した6ファイル全てとする。
- RPPトラックreports系はZIPで来る。
- 広告表示系はCSVで来る。
- 子GAS側の処理内容やURLは変更しない。
- トリガー間隔は現行の1分ごとのまま変更しない。
