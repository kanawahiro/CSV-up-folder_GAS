# 楽天サーチGAS フォルダ自動処理実装計画

## 概要

Google Drive の `01input` フォルダに楽天サーチCSVを入れるだけで、`raku_sa-chi_GAS` が自動で取り込みを実行する構成へ移行する。
既存の手動取込実装を活かし、`importFromFileId(fileId)` を共通入口として使いながら、時間主導トリガーによるフォルダ監視、処理後ファイル移動、ログ記録を追加する。

---

- 対象GASは `C:\\Users\\kg_zk\\Documents\\GitHub\\利益・広告\\raku_sa-chi_GAS`
- 参照方針は以下2つに合わせる
  - `_GAS実装パターン_手動テストからDriveトリガー移行.md`
  - `計画書.md`
- 既存の手動取込関数 `importFromUpload` `importFromFileId` `importRakutenSearchCsv` は維持する
- ファイル名プレフィックスによる親GAS振り分けは今回の対象外
- `01input` に置かれたCSVはすべて楽天サーチCSVとして処理する

## 実装内容

### 1. 定数追加

`raku_sa-chi_GAS/src/コード.js` に以下の定数を追加する。

```javascript
const LOG_SPREADSHEET_ID = '1aYDQl95GRViM1OJOV-5e2NlB-H_6jseXTAHL2PYoAHk';
const LOG_SHEET_NAME = 'log';

const DRIVE_FOLDERS = {
  input: '1hqQhtQ3CKsu07wsrutiTeQUkw3xFmgV5',
  processed: '1i9cqp-ZxLnhTnecyru484-CiOix05hZ2',
  error: '1IRO975sSTLINYdWRfoQpvzkdyq9JguCo',
};
```

### 2. フォルダ監視処理追加

以下の関数を追加する。

- `processInputFolder()`
  - `input` フォルダ内の `MimeType.CSV` を順番に取得する
  - 各ファイルを個別の try-catch でラップして処理する（1ファイルの失敗が他に影響しない）
  - `importFromFileId(file.getId())` を実行する
  - `result.status === 'success'` なら `processed` へ移動する
  - それ以外（エラー戻り値・例外いずれも）は `error` へ移動する
  - すべての結果を `logResult_()` でログシートに記録する
  - LockService は不採用（シンプル実装優先・既存の重複チェックで二重取込を防止）

- `moveFile_(file, destFolderId)`
  - 元フォルダを `DRIVE_FOLDERS.input` として扱う
  - 移動先フォルダへ追加後、入力フォルダから削除する

- `logResult_(file, result)`
  - ログスプレッドシートの `log` シートへ1行追記する
  - シートが空の場合はヘッダー行を自動挿入してからデータを追記する
  - 記録項目は `実行日時 / ファイル名 / status / 取込件数 / メッセージ`

- `setupTrigger()`
  - 既存トリガーを削除してから `processInputFolder` の1分トリガーを再作成する
  - 重複トリガーを防止する

### 3. 既存処理との接続

- CSVの読込と取込本体は既存の `importFromFileId(fileId)` をそのまま使用する
- 既存の戻り値 `status` `message` `rowsImported` を `processInputFolder()` 側で判定とログに使う
- `buildResult_()` の `Logger.log()` は残し、Apps Script 実行ログとスプレッドシートログの両方に記録する

## ログ仕様

ログスプレッドシート `1aYDQl95GRViM1OJOV-5e2NlB-H_6jseXTAHL2PYoAHk` の `log` シートに、以下のヘッダーを用意する。

| A | B | C | D | E |
|---|---|---|---|---|
| 実行日時 | ファイル名 | status | 取込件数 | メッセージ |

- 正常時は `success`
- 失敗時は `error`
- `rowsImported` が空の場合は `0` を記録する
- `message` には既存取込処理の返却メッセージをそのまま記録する

## 実装手順

1. `raku_sa-chi_GAS/src/コード.js` に定数と新規関数を追加する
2. `clasp push` で対象GASへ反映する
3. GASエディタで `setupTrigger()` を一度だけ手動実行する
4. `01input` フォルダにCSVを置いて自動取込を確認する

---

## テスト観点

- 正常な楽天サーチCSVを `01input` に置くと、取込後に `02processed` へ移動すること
- 取り込み成功時に既存スプレッドシートへデータ登録され、差分集計シートも更新されること
- ログシートに `success` と取込件数が記録されること
- 同一期間の重複CSVでは `03error` へ移動すること
- ヘッダー不正や文字コード不正のCSVで `error` が記録されること
- `setupTrigger()` を再実行しても `processInputFolder` のトリガーが重複しないこと
- `01input` が空のときは何もせず終了すること

---

## 補足

- GASにはDriveフォルダ追加の即時ネイティブトリガーがないため、時間主導トリガーによるポーリング方式を採用する
- 今回は `CSV-up-folder_GAS` 親GASの実装ではなく、`raku_sa-chi_GAS` 単体の自動処理化を対象とする
- 将来的に親GAS方式へ広げる場合でも、子GAS側の `importFromFileId(fileId)` はそのまま再利用できる
