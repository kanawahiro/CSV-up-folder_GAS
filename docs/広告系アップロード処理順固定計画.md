# 広告系アップロード処理順固定計画

## 目的

入力フォルダに広告系・検索系の複数ファイルが同時に入った場合でも、Google Drive のファイル列挙順に依存せず、決めた順番で処理する。

基本ルールは「前の処理が成功して終わったら次を実行する」。途中でエラーが出た場合はそこで停止し、今回の順番制御対象ファイルは `input` に残さず `error` へ移動する。

## 固定する処理順

### 1. RPPトラック系

以下を RPPトラックで処理する。

1. `YYYYMMDD_item_list.csv`
2. `rpp_item_reports_limelimedou_YYYYMMDD*.csv`
3. `rpp_keyword_reports_limelimedou_YYYYMMDD*.csv`

例:

- `20260410_item_list.csv`
- `rpp_item_reports_limelimedou_20260411072441328.csv`
- `rpp_keyword_reports_limelimedou_20260411072446699.csv`

### 2. 広告表示

RPPトラック系がすべて成功した後に、広告表示用の 2 ファイルをペアで処理する。

例:

- `rpp_item_keyword_limelimedou_20260411072506159.csv`
- `rpp_keyword_ranking_limelimedou_20260411071609_1775859911172.csv`

### 3. 楽天サーチ

広告表示が成功した後に、楽天サーチを最後に処理する。

例:

- `act_20260401_20260409_427986.csv`

## 実装方針

`processInputFolder()` の中で、入力フォルダ内のファイルを最初に全件収集してから分類する。

分類後、以下の順番で処理する。

1. `clickpostReport` は現行通り専用処理する
2. 順番制御対象ファイルを日付キーごとに分類する
3. RPPトラック系を固定順で処理する
4. 広告表示ペアを処理する
5. 楽天サーチを処理する
6. 順番制御対象ではないファイルは既存ルールで処理する

RPPトラック系の `rpp_item_reports` と `rpp_keyword_reports` は、既存の `rpp_` prefix 汎用ルールより先に判定する。これにより、RPPトラック対象として明示的に順序制御できるようにする。

## エラー時の扱い

順番制御対象の処理中にエラーが発生した場合は、後続処理を実行しない。

エラー時の扱いは以下とする。

- 失敗したファイルは `error` へ移動する
- まだ処理していない順番制御対象ファイルも `error` へ移動する
- `input` には順番制御対象ファイルを残さない
- 未処理で `error` へ移動したファイルにもログを残す
- ログメッセージには `前段エラーのため未処理でerror移動` のように理由が分かる文言を入れる

順番制御対象ではないファイルは、この一括エラー移動の対象外とする。

## 追加する判定

RPPトラック系として以下のファイル名パターンを追加する。

- `^\d{8}_item_list\.csv$`
- `^rpp_item_reports_limelimedou_(\d{8})\d+\.csv$`
- `^rpp_keyword_reports_limelimedou_(\d{8})\d+\.csv$`

広告表示系は既存のペア判定を利用する。

- `^rpp_item_keyword_limelimedou_(\d{8})\d+\.csv$`
- `^rpp_keyword_ranking_limelimedou_(\d{8})\d{6}(?:_\d+)?\.csv$`

楽天サーチは既存の `act_` prefix 判定を利用する。

## 成功条件

以下を満たせば完了とする。

- 複数ファイルを同時に入れても、RPPトラック系、広告表示、楽天サーチの順で処理される
- RPPトラック系の内部順が `item_list`、`item_reports`、`keyword_reports` になる
- 前段が成功した場合だけ次の処理へ進む
- 前段でエラーが出た場合は後続処理を実行しない
- エラー時に順番制御対象ファイルが `input` に残らない
- 成功・失敗・未処理error移動の結果がログシートに残る

## テスト観点

- 6 ファイルを同時に配置し、指定順に子GASが呼び出されること
- RPPトラック系の 1 件目で失敗した場合、広告表示と楽天サーチが実行されないこと
- 広告表示で失敗した場合、楽天サーチが実行されないこと
- 広告表示ペアで失敗した場合、ペア対象が `error` に移動すること
- 広告表示ペアの片方が不足している場合、対象ファイルを `input` に残さず `error` に移動すること
- 同一日付で同種ファイルが重複している場合、対象ファイルを `error` に移動すること

## 前提

- 今回の順番制御対象は、RPPトラック系、楽天サーチ、広告表示系のみとする
- `clickpostReport` とピッキングCSVは今回の順番制御対象外とし、現行挙動を維持する
- 子GAS側の処理内容は変更しない
- 親GAS側で処理順とエラー時の移動方針を制御する
